# Receipts: Swanky popsicle RB01 re-check

RB01 is an experimental benchmark adapter. Its functional and performance results do not establish suitability for sensitive data or production use.

The constructors initialize separate RNG consumers from the same seed. The reporting seat observed overlapping streams within each party and matches between some generated bytes and protocol traffic. The security consequences remain unverified.

## Who, under what authority, where

- **Executor:** Seat 3 (Claude Code), the session that owns this lane. No
  other seat and no other host executed anything recorded here.
- **Authority and scope:** the 2026-10-09 order to this lane. It asked the
  lane to re-check RB01 items 1–6 against upstream and to build minimal
  standalone reproductions in Rust, with synthetic data only, in WSL.
  Upstream posting was held for the founder's word in chat. Every run
  stayed within that scope: one host, synthetic inputs, two parties inside
  one process. No data or results were sent off the host. The run-2 and
  run-3 scripts did contact GitHub, with `git fetch`, to record Swanky's
  `dev` head. Run 3's `environment.txt` records the authority line; its
  "nothing sent off the host" wording refers to data and results.
- **Disclosure bound to the run:** each program prints its notice first, so
  every run-2 and run-3 log carries the notice version that program showed.
  The program bytes are pinned in `DIGESTS.md` for run 3, and below for run
  2 and for run 1's four `repro_*` programs. Run 1's `probe_spin` bytes
  were not kept.

## Instrumentation history

- `repro_set_sizes`. Before its first build, the panic hook was changed to
  keep every panic of a session instead of only the last. Run 3's version
  also tallies the panic messages of every panicking session (runs 1 and 2
  printed only the first per size) and adds a 600 s watchdog.
- Printed notice. Version 1 was added for run 2. Version 2, used in run 3,
  adds two lines. The first names what the program deliberately makes
  upstream do (panics, sessions that do not complete, or an encoding
  collision; the wording differs per program). The second lists unresolved
  risks: one host, one target, behaviour elsewhere untested, no security
  property established. Version 2 also states a time limit for every
  program. It does not name observation 6, for the reason in the README's
  section "Informed consent at the point of use".
  `repro_input_encoding` gained a 60 s watchdog, and its limit text now
  says "three encoding comparisons".
- `probe_spin`. Version 1's frame filter dropped every frame whose symbol
  mentioned the probe's RNG type, which all generic frames do. So every
  sample was attributed to `swanky_channel::Channel::with_sizes`, and that
  version's outputs were discarded as instrument error, not evidence.
  Version 2 added `PROBE_RAW=1`, which prints one full backtrace; it showed
  `<swanky_oprf_kmprt::Sender>::process_oprf_output` at `lib.rs:243:25`.
  Version 3 matches only a symbol's leading path and drops a trailing
  generic-argument list. Its outputs are the ones recorded. The committed
  file is version 3 plus the notice, one doc line about `PROBE_RAW`, and the
  doc wording "has not completed".
- Observation-6 instrument: its history is held with it.
- Package location. Run 2's script read the programs from
  `docs/audits/swanky-popsicle-rb01/repro`, the package's draft location at
  the time. The package then moved to
  `docs/upstream/2026-10-09-swanky-popsicle-rb01/`, the precedent for
  upstream packages, without changing those bytes. Run 3 read from the new
  location.
- Post-processing (all runs). `$HOME` was replaced by `~` in every saved
  log, including the three kept run-1 files.
  Each script's own `SHA256SUMS` and source-digest lists were checked
  (`sha256sum -c`, all OK) and then replaced by the package's `DIGESTS.md`,
  because the repository's secret scan requires a same-line marker on every
  64-hex line.
