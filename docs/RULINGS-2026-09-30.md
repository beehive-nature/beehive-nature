## W1 — the VENDOR-HELD class

A browser-resident feature that needs no operator-run host (so it is not
SERVER) but whose substance — the runtime, and for built-in AI the model
weights — lives in the vendor's browser binary. It dies the day the vendor's
build stops shipping it, and its bytes can never be L-VERIFY'd or SRI-pinned
by the page. Every VENDOR-HELD use is enhancement-only and its loss must
degrade to a working page (this is the onboarding law restated for AI).

## W2 — model-custody wording (the receipt law for built-in AI)

A receipt that used a browser-provided model cites the **browser and version**
that produced it, never bytes — there are no bytes to cite. No surface may
call a built-in API "local", "on-device", or "private": the spec itself
allows cloud implementations (translation-api explainer, A98); such a claim
is a per-browser measured fact or it is unsayable. Security wording capped at
"browser-provided" (crypto-language law applies).

## W3 — no surface hard-requires a disabled-by-default API

WebNN (`navigator.ml`) is a W3C CR Draft (2026-09-10) that no engine enables
by default (caniuse read 2026-09-30: 0% usage). Adoption trigger, banked:
**default-on in one stable engine AND polyfill parity**. Until then no surface
may require it; feature-detect and degrade. This generalizes: a spec's
maturity is never a shipping fact.

## W4 — reader-side browser translation (the S1 law)

`surfaces/browser-translate.js` (shipped on `surfaces/index.html`) is the
only sanctioned shape: feature-detected, **icon-only** (the browser's offer
wears the browser's words — the estate authors zero new visible strings),
mounted in the language host as census chrome (`#brtrctl`, lang.js), one
click, reversible, reload resets, **no storage writes ever** — the estate's
keyed floors stay ABSOLUTE and the corpus is never touched. Browser
translation is the reader's convenience for unkeyed prose; it is never a
substitute for keying (founder reframe 2026-08-29: the gap is keying, never
translation).

## W5 — the machine door (the WebMCP S4 law)

One surface (`surfaces/vending.html`) registers ONE read-only tool via
`document.modelContext.registerTool()`. The payload is a **fixed whitelist**
(public price sheet only): the reader's typed name and its derivations never
cross a machine door (opacity law, bMAIL doorbell pattern). A permissions
refusal is silence, not an error. Nothing member-facing rests on WebMCP:
WebKit opposes, the origin trial ends when the vendor says — the tool's
disappearance must cost the estate nothing.

## W6 — patterns banked as wording (advisory until code cites them)

- **Weightless probe** (DAOP): a placement decision about a model ships the
  model's shape, never its weights.
- **Callee self-assessment**: the device that would run the model says
  whether it can.
- **Tiers, not fingerprints**: capability answers are coarse strings
  ("fast"/"slow"), never device identity.
- **A form is a manual**: keep estate forms clean and agent-legible — a form
  is already a capability description.
