# 2026-09-07 — cloud-env: a Cursor Cloud Agent development environment

Lane: cloud-env. Seat: Cursor Agent (committer), founder-authored per §7.

## What landed

A repository-managed Cloud Agent environment so a fresh agent boots straight
into the same green CI runs on every push, and the static estate is served and
browsable without any hand-setup.

- `.cursor/environment.json` — repo-managed config (highest-precedence source).
  - `install`: `bash .cursor/install.sh`
  - `terminals`: `surfaces-hub` → `python3 -m http.server 8080 --bind 0.0.0.0`
  - `ports`: 8080 (the front door / surfaces hub)
- `.cursor/install.sh` — idempotent bootstrap that MIRRORS
  `.github/workflows/tests.yml`, so "it built here" and "CI is green" are the
  same fact:
  - `git config core.hooksPath .githooks` (the secret-scan + §7 hooks)
  - `cargo build --workspace --locked` (34-crate kernel)
  - `cargo build --locked --manifest-path rust/bsafe-host/Cargo.toml`
  - `npm ci` in `e2e/`, `key-build/bdid-key/`, `ops/voice-scribe/`
  - `npx playwright install --with-deps chromium` for the browser suites

No dev servers live in `install` (it must terminate); the hub server is a
`terminals` entry so its log and lifecycle stay visible.
