## P1 — the validation seal does not cover derived approval state

`ValidatedPlan::approve_ceiling` is still publicly mutable.
`is_internally_consistent` checks only the inner plan; `revalidate` returns
a fresh object but does not repair/refuse the caller's altered derived field.
`validate_transaction(Approve)` uses that unsealed `approve_ceiling`.

Repro: obtain the valid base plan (36 atto approval), set the public derived
ceiling to 1,000,000, and construct that amount's approval calldata.
Both `is_internally_consistent` and `revalidate` succeed; the original handle
accepts the excessive approval transaction. Its sealed underlying plan still
specifies 36. This is a public API composition failure, not a forged RPC.

Required: make validated state and derived fields private, exposing immutable
getters, or enforce all derived invariants at every consuming API. Never
trust caller-modifiable derived amounts. Add an approval-path regression
(compile-time immutability is acceptable if the mutation API is eliminated),
and retain healthy approval controls. The previous mutation regression only
tested changing the inner plan, not this derived field.

## P1 — impossible fee evidence can erase a reservation

`reconcile_reservation` multiplies supplied gas/price and clamps downward,
but does not validate either field against the signed transaction first.
Repro: record an intent and valid synthetic signed transaction, then submit
a reverted receipt with `gas_used = tx.gas_limit + 1` and effective price 0.
`record_outcome` succeeds; the product is zero and the reservation is released.
Gas used above the signed gas limit is impossible even under the module's
explicit trusted-RPC assumption. Clamping is not validation.

Required: reject contradictory/impossible receipt fields before mutating
state or reducing a reservation. Check status domain, gas used versus limit,
effective price versus the signed envelope's bounds (including legacy price
consistency), and complete fee-evidence pairs. Missing or invalid evidence
must not release exposure. Keep legitimate zero-price test-network behavior
distinct from this impossible gas-use case. A compromised RPC remains outside
the proof scope; these are locally detectable consistency requirements.
