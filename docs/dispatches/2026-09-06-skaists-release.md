# skaists release — founder-approved New bee default

The founder approved the New bee view and explicitly authorized publication:

authorization, the copy pass, the publishing boundary and the recovery path.
The initial implementation is recorded in

## Default and wording

`surfaces/register.js::pref` returns `bee` when there is no saved valid choice
or when storage is unavailable. It remembers an explicit Raver or Cypherpunk
choice. The generated HTML starts with `body data-reg="bee"`, including the
no-JavaScript version. No preference reset is imposed on returning readers.

The founder also requested grammar corrections and wording improvements as
translations are checked. A fresh Astra text-review subagent, with inherited
model and effort, reviewed the 32 new atlas keys across English and all 28
docked translations (928 cells). These remain machine-reviewed drafts;
neither full native-speaker validation nor a fully translated estate is claimed.

The copy pass removes an ambiguity that made people sound like something
being manufactured, aligns the revised introduction across every language,
and corrects the Tatar heading. Search now reads as a label followed by a
count, avoiding constructions such as “1 results.” Footer count captions use
existing corpus keys. The fleet evidence sentence is grammatical while
retaining its computed value and the original university-smoke assertion.
An additional 29-cell review of the legacy buds description corrects meaning
drift in Gaelic and Tatar (including a changed controlling actor and an
invented opening condition), founder-control grammar in Danish and Turkish,
and the missing English preposition. The adjacent Gaelic empty-place wording
also changes “whip” to “vacant place.” All remain machine drafts.
Founder quotations, artwork, the three approved welcome actions, named limits
and all directory destinations remain intact.

The 714-key corpus's complete cells are not the same thing as complete page
translation: generic tool titles, some legacy prose and technical control
messages still need an editorial pass. That broader work should be reviewed
in bounded language groups with receipts, without relabelling machine drafts
as human attestations. zCode's independent review docket is issue #6; it had
not been claimed when this release preparation began.

## Publish and recovery boundary

The existing GitHub Pages source is `main:/`, with CNAME `skaists.dev`.
At preparation, its last successful build was
`5b67c302f108a2648fe90ed702c9859944859080`. Publication uses a local merge
with the canonical founder author / Astra committer / parsed co-author
trailer, from a separate seat-owned release worktree. No GitHub API merge,
force push, shared-checkout staging or OCI service edit is part of this lane.

The candidate must pass atlas regeneration, registry parity, corpus integrity,
the directory suite and all existing CI checks before main is advanced. The
integration commit message records the exact candidate and main parent.
The publishing result and live byte-parity evidence belong to the release
comment on PR #5; this preparation dispatch does not pre-claim success.

Verification compares unversioned HTTPS responses for the root redirect,
generated page, style, scripts, corpus and artwork against the released Git
blobs. It checks the served version, not just whether a URL returns 200.
The existing browser CI is exercised; no additional manual browser visual
review or approval by the matriarch is claimed.

If a release regression requires rollback, make a forward revert of the
integration merge with first parent as mainline, in a fresh seat-owned
branch. Preserve the founder's design-priority rule and newer independent
work while resolving that revert; rerun the gates and publish through the
same Pages path. The integration's first parent is the exact prior tree.
Do not reset or force main. The byte check must confirm the restored UI.
