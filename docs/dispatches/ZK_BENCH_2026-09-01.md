# THE ZK BENCHMARK — the deciding number, measured — 2026-09-01

The founder said GO on the one benchmark the Zano raid left open. It ran to
completion in a lab on the founder's own laptop (WSL, Spring v1.2.2 + CDT
4.1.1, artifacts in `C:\Users\travi\zkbench`). **Verdict: the sovereign
privacy layer is UNBLOCKED — one Groth16 verification costs ≈ 2.4 ms of
compute on commodity hardware, comfortably inside per-transaction CPU
budgets.**

## 1 · AVAILABILITY — settled by chain state, not by deploying

- **CRYPTO_PRIMITIVES is ACTIVATED on Vaulta mainnet**: activation_ordinal
  16, digest `6bcb40a24e49…`, activated at block **269,183,454** (verified
  via `get_activated_protocol_features` on eos.api.eosnation.io). Any fresh
  contract can call the intrinsics today.
- Node software at both mainnet and jungle4 API endpoints: **Spring v1.2.1**
  — the CDT 4.1+ / Spring 1.0+ requirement is met by the chain itself.
- The CDT contract API is documented and plain: `alt_bn128_add`,
  `alt_bn128_mul`, `alt_bn128_pair`, `mod_exp`, `blake2_f`, `sha3`, `keccak`,
  `k1_recover` (`eosio/crypto_ext.hpp`).

## 2 · THE GATE, caught empirically

On a fresh local Spring chain, `setcode` of a contract importing
`env.alt_bn128_pair` fails with **"env.alt_bn128_pair unresolveable"** — the
intrinsic exists in the VM but is inert until CRYPTO_PRIMITIVES activates.
The bootstrap path that works: `POST /v1/producer/schedule_protocol_feature_
activations` with the PREACTIVATE_FEATURE digest → deploy an activate-capable
contract → `activate` the target digest. (Our local chain hit a digest-
validation oddity in the last step — the preactivate returned an unrecognized
digest different from the one sent; unresolved locally, noted here because
the MAINNET availability question never depended on it — mainnet state is
already active.) The wasm-level intrinsic name is `env.alt_bn128_pair`
(module `env`).

## 3 · THE NUMBERS — the exact compute core the host functions call

Spring's `crypto.cpp` implements the alt_bn128 host functions over the
vendored [AntelopeIO/bn256](https://github.com/AntelopeIO/bn256) library. We
benchmarked THAT library directly (g++ -O3, single thread, WSL on the
founder's laptop — commodity hardware class; block producers run faster):

| operation | measured | note |
|---|---|---|
| g1 add | **695 ns** | the `alt_bn128_add` core |
| g1 scalar mul | **120 µs** | the `alt_bn128_mul` core |
| pairing_check (1 pair) | **1.76 ms** | |
| pairing_check (2 pairs) | **2.40 ms** | |
| pairing_check (3 pairs) | **3.05 ms** | |
| **Groth16-shaped verify (neg + 2-pair check)** | **≈ 2.44 ms** | **the number that decides** |

Marginal per-pair cost ≈ 0.64 ms (Miller loop) + ≈ 1.1 ms fixed (final
exponentiation) — the shape every BN254 SNARK verifier shares.

## 4 · TRANSLATION TO CHAIN ECONOMICS

Against classic Antelope budgets (500 ms blocks; 150 ms max transaction CPU;
200 ms max block CPU — the values in Spring's shipped genesis files):

- one Groth16 verify ≈ **1.6% of a transaction's CPU ceiling** — a verifier
  action is an ordinary transaction, not a budget event;
- a block could verify **~80 proofs** at full CPU usage (single-threaded
  assumption — producers bill what they measure);
- storage side (already measured in SPEC-VENDING-1 §sizing-basis): a
  commitment/nullifier row ≈ **$0.007**.

A private-notes contract — commitments + nullifiers as RAM rows, spends
proven by Groth16 over BN254 — is computationally and economically ordinary
Vaulta work. **The sovereign option (Zano raid, Option 2) is green.**

## 5 · A CORRECTION TO THE RAID — BLS12-381 IS LIVE TOO

The raid said "BN254 only — BLS12-381 has no host function." **Wrong for
today's chain state:** Vaulta mainnet ALSO has **BLS_PRIMITIVES2** activated
(ordinal 21, digest `63320dd4a5…`, confirmed against Spring's own feature
registry), and mainline reference-contracts already import `env.bls_pairing`.
BN254 remains the zero-friction path (CDT 4.1 wraps it, Ethereum-verifier
heritage); BLS12-381 is available for the systems that need it — the raid's
scope fence moves from "impractical" to "unwrapped but present."
