## Repairs

- `flushEarlyPaint` parses moov and the next box headers without waiting for
  the 2 MiB preview threshold introduced in #277. The 1,187,514-byte VP9/Opus
  fixture could never cross that threshold: no time plan, countdown or device
  verdict ran before whole-file playback. Preview uses about one media second,
  with a 256 KiB floor and the existing 2 MiB ceiling. The large-file skip and
  32 MiB start guard are retained.
- `paintSrc` waits for current frame data, not metadata dimensions alone.
  An incomplete start can retry only after `extend`'s additional two-second
  media budget; it no longer permanently locks progressive playback out.
  Preview still gets one attempt; source replacement is not per chunk.
- #278 correctly avoided source replacement when the full download arrived
  during playback, but its remaining partial Blob was stranded: `done` and
  the hidden progress bar disabled all tail-handoff paths. `needsFinalTail`
  keeps edge/error/ended handling active until the painted copy contains every
  media byte. Completion itself still leaves current playback alone.
- A rolling rate window could retain the earlier fast burst after a door
  slowdown. The planning rate now also takes the latest arriving chunk's rate,
  so the wait uses the slower measured evidence immediately.

The fast-door regression now continues to the end, rather than ending after
the first half-second of playback. Without the tail repair it failed with
`page.waitForFunction: Timeout 25000ms exceeded`. Failure diagnostics include
the existing engine snapshot and media log; no live network is involved.
