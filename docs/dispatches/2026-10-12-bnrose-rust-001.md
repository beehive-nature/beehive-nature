## The one vertical slice

```
canonical intent (WB001 envelope, btungsten-wb001 — unchanged, SAW-proven
codec, Ed25519 binding via libcrux =0.0.9)
→ authority/policy validation (supervisor verifies the WB001 signature
  host-side; the untrusted worker re-derives structural + policy + clock
  verdicts from the envelope alone — keys never enter a worker)
→ bounded worker execution (the SAME authoritative logic, one core crate:
  native rlib, and wasm32 behind pinned Wasmtime — fuel + epoch + memory
  caps, zero host imports: the module cannot call out, read, write, or
  spend; the only externally-consequential door is host-side and opens
  only after the Dispatched journal record is durable)
→ durable state transition (append-only HMAC-SHA256-chained journal; the
  operation identity, authorized scope, resource reservations, and
  execution progress are persisted and fsynced BEFORE any external effect)
→ verifiable receipt (Ed25519 statement binding op id, envelope hash,
  terminal state, effect digest, journal head — independently checkable
  with the public key alone)
→ recovery on a clean replacement worker (fresh process, original worker
  and its local state deleted; state rebuilt ONLY from the authenticated
  journal + effect ledger, cross-reconciled both directions)
```

## Honesty commitments (written before the battery runs)

- **UNKNOWN is a preserved state, not a gap.** An operation whose response
  was lost after dispatch stays UNKNOWN across restarts. Absence of a
  response NEVER authorizes a replacement operation; a fresh attempt
  requires a fresh authorization (fresh nonce) through normal admission.
- **Deduplication — who enforces what, named.** No-second-logical-operation
  is enforced by the supervisor's journal ((authority, nonce) uniqueness
  across all admitted operations, authenticated append-only). No-duplicate-
  external-effect is enforced by the effect ledger's idempotent apply
  (keyed by operation id, digest-bound). Exactly-once external effects are
  NOT claimed from the local journal alone: beyond this single-supervisor,
  single-ledger slice, exactly-once would have to be a property of the
  external system's own transactional commitment — that boundary is stated
  wherever the claim could be misread.
- **WB004 retry failure rides this battery as a NON-SPENDING fixture**
  (`test/wb004-retry-lost-response`): operation succeeds, its response is
  lost, the worker restarts — recovery must complete the SAME logical
  operation from ledger evidence with exactly one effect row and no second
  admission.
- **Acceptance before benchmarks.** The battery earns, in order: valid-input
  acceptance (independent re-verification of every receipt field),
  invalid-input rejection (every named refusal convicted by a vector),
  mutation controls (planted implementation faults must be CONVICTED by the
  battery going red — TEETH), exact native/Wasm agreement (byte-identical
  verdicts for every vector through both backends, enforced at runtime by
  the paranoid dual-run, not only at test time). Benchmark numbers are
  labeled with workload and hardware and extrapolate nothing — least of all
  ten-billion-user capacity.
- **Preserved evidence stays preserved.** The WB001 SAW/Cryptol receipts
  are untouched; nothing in this lane modifies `btungsten-wb001(-core)` or
  `bsigner`. Any proof my changes could have affected is re-earned by the
  battery itself; where a link is only sampled, the receipt says sampled.
