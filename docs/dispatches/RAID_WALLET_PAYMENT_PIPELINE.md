## Executive Summary (<= 5 lines)
Six projects assessed; verdicts: five PATTERN (flex, AO Wallet, Wander, everPay, Paragraph) and one LEAVE (Irys). NONE is TAKE-eligible as a live dependency — every value-add over BNR's baseline (arweave-js + arbundles + self-hosted ar-io-node + native JWK) sits behind a hosted endpoint, custodial operator, token gate, or closed core. Single most important finding: NOTHING here funds a user's AR upload capacity non-custodially — flex settles PST↔PST only, Irys/everPay/Paragraph custody the funding path — so BNR's "fund user AR wallets" problem stays on the sovereign Turbo-credit / native-JWK top-up path and must be solved in-house. Highest-value extracts: Wander's injected-provider + per-permission + configurable-gateway consent model, and the arbundles optimistic-receipt/deadline-height bundler pattern (the open half of Bundlr). Canonical cautionary tale: Irys captured ~70–80% of Arweave throughput on a closed bundler, then forked to its own L1 (UNVERIFIED throughput figure — secondary source).
