# bViEw: bound direct startup through the first frame

The founder reports 40+ seconds of apparent inactivity followed by cycling, and over a minute for the 11 MB video. Source inspection found serial waits: direct setup had a 45-second deadline, that deadline was cleared after service-worker attachment, and paintSrc then received another 45 seconds. Range reads used the outer playback signal, so the startup abort did not cancel a stuck first-frame read.

The direct-plus-relay option now has one eight-second startup budget covering SDK import, node connection, address resolution, worker attachment and first decoded frame. The status reports the current stage and elapsed seconds. The startup deadline remains active through the first frame, and range reads use its cancellation signal. Failed attempts abort outstanding reads and close the direct session before the existing relay path starts. Sustained stalls after playback get five seconds rather than fifteen, retaining the existing playhead and pause behavior. Cypherpunk receipts expose the startup budget and actual elapsed attempt separately from network bandwidth. This improves fallback responsiveness; it does not claim to accelerate Autonomi node discovery or add viewer seeding.

Focused acceptance: six tests, six passes, zero failures/cancellations/skips, exit 0, 79286.8039 ms. These include hung connection and hung first-frame reads, cancellation of a stuck read, real decoded VP9 frames and seeks, connection reuse, one relay request, playhead preservation, and pause/progress cancelling fallback. The browser and SDK media worker are real; the network reader is mocked in this suite.

Real-network candidate acceptance uses an owned fresh Chrome profile on the public origin with only this candidate HTML substituted. The official public demo is 11572127 bytes and 12 seconds at 1280x720. Direct connected in 3.244 seconds but did not resolve the file within the eight-second budget. Relay then produced a first frame at 8.8596 seconds from the founder action; all bytes arrived at 9.795 seconds. Playback reached 12 seconds with zero dropped frames in the final source and no page errors, exit 0. This is candidate evidence, not a deployed-byte receipt. The relay-only baseline returned first frame 1.0269 seconds and all bytes 1.9116 seconds; its initial harness assertion used the wrong playhead property and exited 1 despite reaching the end, then the harness was corrected before candidate acceptance.

The wider initial local regression run reports 21/22 passes and one failure in the fast relay test's height-preservation assertion: its first recorded previousHeight is zero, while subsequent handoffs retain 199.125 px and all copies contain real pixels. An isolated unchanged-main check and hosted CI determine attribution; this failure is not reported as a pass. Estate-check and git diff --check pass. Final hosted and public receipts will be recorded with the PR.
