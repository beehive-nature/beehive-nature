# 2026-10-13 · EOSVM-WALLET-001 — native EOS VM as a runtime for BNR wallet contracts

Order EOSVM-WALLET-001, delivered from `wt-eosvm001` (branch
`eosvm-wallet-001`). Everything is additive: `scripts/eosvm-wallet-001/`
(component + engine harness + chain probes + receipts). No existing
implementation was replaced; no production node, no new chain, no mainnet
spending, no private keys.

## The one-line answer

**Retain the chain runtime as-is; add the standalone eos-vm library — the
same engine Spring v1.2.2 pins — as an optional off-chain deterministic-
verification backend** (interpreter first, JIT for CPU-heavy work), and keep
tuning decisions OUT of nodeos until two receipted blockers (feature-
activation bootstrap; freestanding-wasm dispatch) are owned and cured. No
measured result merits rejecting any candidate.

|---|---|---|---|
| pure-wasm loop, 20M iters (p50) | 899 ms | 149 ms | **JIT 6.0×** |
| dbloop 500×(put+get) (p50) | 126 µs | 164 µs | **interpreter ~1.3× FASTER** |
| parse/instantiate 1.2 KB (p50) | 47 µs | 60 µs | parity |

| memory.grow to 4096-page cap | clean | clean | — |

Component — the zkrcount PLONK gate (verbatim estate headers; explicit

## Ranked recommendation

1. **Retain as-is** — the chain-side runtime (Spring pinned line). Nothing
   measured warrants a change; the engine underneath is exactly the pinned
   eos-vm.
2. **Add an optional backend**: standalone eos-vm (EOS VM License, not BSL)
   for off-chain deterministic verification. The component proves the
   pattern: verbatim estate verifier headers, explicit 4-import host
   interface, behaviorally-identical interp/JIT/native. Interpreter is
   adequate at verification frequencies (host crypto dominates); JIT gives
   6× on CPU-heavy wasm.
3. **Tune (when it matters)**: runtime choice per workload — the
   interpreter is FASTER than the JIT on host-call-bound paths (measured);
   JIT only wins on pure-wasm compute.
4. **Optimize a demonstrated bottleneck**: none demonstrated beyond the
   above; the harness now exists to demonstrate one if a workload demands.
5. **Reject**: nothing measured merits rejection.

**Follow-on owners required** (per the order's last clause): (a)
feature-activation bootstrap on v1.2.2+ dev chains — five failed paths
documented, reproducible in `chain/`; (b) the freestanding-wasm dispatch
anomaly — reproducible via `chain/probefree.c` + `chain/spincheck.js`.
Neither blocks the recommendation; both block deeper chain-side receipts.

**Operator hardware**: engine footprint is small (harness RSS ≈ 5–6 MB,
interp and JIT); nodeos OC tier-up defaults to a 1 GB code cache and 1
compile thread — a chain-operator cost, not an off-chain-embedding cost.
