## The durable lifecycle (surfaces/bdrop.js v2, bdrop.html)

prepared → authorized → signed → submitted → confirmed → reconciled, with
diverged as the refusal state. The outbox (`bnr.bdrop.outbox.v1`, localStorage)
persists scope, body bytes, the signed transaction and a bMeter-shaped event
log (events and references, never contents — the bchat-core law) **before**
submission, and never a secret. On load and on demand the desk reconciles
against the chain FIRST: a landed drop is confirmed, never re-published; a
permlink holding different bytes is reported diverged and never edited; an
unexpired signed transaction can be re-broadcast byte-identically without the
key; an expired one says it needs the key. Pre-flight reads the chain before
any signature — duplicates reconcile instead of re-publishing.

**Key custody, on the estate's wallet law** (wallet.html's outbox + one-paste
lanes were the pattern; nothing new invented): the WIF is parsed once, held as
zeroable `Uint8Array` seed bytes in tab memory, bound to an authorization
scope — author, permlink, body digest, disclosure version, endpoint — hashed
and shown when live. Within the bound scope it signs repeatedly without
re-prompting; any scope change requires the key again; authority never
expands silently. Erasure is honest, not theatrical: field cleared, bytes
zeroed, references dropped — the page says wiped-by-construction and claims
nothing about transient string copies. No key material ever reaches storage
(the suite asserts it).

**Preservation beyond the chain**: the chain itself is the primary durable
record (content-is-chain); this tree mirrors. After confirmation the desk
composes the preservation bundle (receipt + edition + manifest sha-256s) and
offers hosted-Autonomi storage through Agent 20's shared module
(`ant-pay.js` `createHosted`, PR #391, merged `42c466b56`) — priced invoice,
the founder's wallet signs, module-enforced ceilings, nothing spent silently;
a `bpay.ant.reconciled/1` event lands in the outbox on success. Coordination,
not duplication: the purchase UI is the shared module's own flow.
