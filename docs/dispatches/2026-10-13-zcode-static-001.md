## The red, reproduced

`node scripts/build-stack-surfaces.mjs --check` on the base commit exits 1
with `Error: Surface directory needs regeneration` — the same failure as
`tests.yml` run `38420194057`, job `115375178800`, in the issue. The step
before it, `build-stack-inventory.mjs --check`, passed there and passes here.

## Root cause — one stale attribute in one generated row

Owning commit: `a4df32921` ("bdrop: the inclusion verifier earns its name…")
bumped the cache-buster on `surfaces/bdrop.html`'s script tag from
`bdrop.js?v=5` to `bdrop.js?v=9` and landed without regenerating the stack
directory. The generator (`scripts/build-stack-surfaces.mjs`, row template)
embeds each page's raw script `src` querystrings into that row's `data-search`
attribute, so the directory held `?v=5` while the page said `?v=9`. Nothing
else drifted: regeneration changes exactly **one line** of
`surfaces/stack.html` — the bdrop row — with `git diff --stat` reporting
`1 file changed, 1 insertion(+), 1 deletion(-)` and `git status --porcelain`
reporting no other modified path.

## The repair

One generated-file rider, produced by the owning script itself:

```
node scripts/build-stack-surfaces.mjs
```

No hand-edit of generated output, no fixture weakening, no scanner loosening,
no #416 footer edits, no baseline relaxation, no broad rebuild. The
"Undeclared interactive dependencies" log lines named in the issue were left
alone — they live inside intentional genealogy negative controls, not this
lane's blocker.

## Guard question — no new regression warranted

Issue step 3 allows a focused regression only if the generator lacks a guard.
It does not lack one: `--check` *is* the guard, CI runs it on every push, and
it fired correctly on main. The failure was a commit changing a declared
generator input without running the generator — a process miss the existing
gate already catches. Adding a second test would test the test.
