## What changed

**WB001 (intent binding).**

- `crates/btungsten-wb001-core` is the model: the canonical envelope
  encoder, the UTF-8 DFA, the validity predicate, offsets and byte
  dispatch, written function for function against
  `wb001-cryptol/BTungstenWB001.cry` (renamed from `Intent.cry` so the
  file carries its module name; Cryptol imports resolve by file name).
- `crates/btungsten-wb001` adds the strict decoder (it refuses malformed
  UTF-8 through the proven DFA), the UTF-16 input boundary, the refusal
  codes, and Ed25519 through `libcrux-ed25519` =0.0.9 (safe Rust compiled
  from HACL*, F*-verified for memory safety, functional correctness and
  secret independence).
- The JS module and its three suites are retired. The battery is ported
  row for row to `crates/btungsten-wb001/tests/wb001/` and drives the
  model. The pinned vectors and bridge are now generated by
  `tests/wb001/pin.rs`; a drift gate requires the committed files to equal
  a fresh derivation byte for byte. Regenerating from the Rust model
  reproduced every envelope and refusal the JS twin had pinned; only the
  provenance text changed.
- `wb001-saw/rust.saw`: EQUIVALENCE, 11 `mir_verify` obligations, the
  Rust model equal to the spec for every input in each domain.
- `wb001-saw/injective.saw` + `WB001Injective.cry`: `wireInjective`
  PROVEN for every pair of valid intents, by a first-difference ladder
  (20 rungs, each required by name).
- `wb001-cryptol/Ed25519.cry`: RFC 8032 Ed25519 as an executable Cryptol
  spec, the missing algorithm artifact. Its SHA-512 round constants and
  initial hash are computed from the FIPS 180-4 definitions, not
  transcribed.
- `wb001-ed25519-oracle.{mjs,json}`: 24 OpenSSL-signed rows (refused
  unless OpenSSL first reproduces the RFC vectors). libcrux, dalek and
  the Cryptol spec must each match byte for byte.
- `.github/workflows/wb001-saw.yml` runs it all (SAW 1.6 by digest,
  mir-json at SAW 1.6's own pin, shared cache with WB002).

**WB002 (the 2021 specimen).**

- `crates/btungsten-wb002` is the model (the JS port is retired). Its
  sovereignty definition is the SAW-proven
  `btungsten_wb002_core::sovereign` of each asset's table status; on the
  Adapter profile every sovereignty-moving NFT/NTT action is replayed
  through the proven `step`, and the model panics if tables and proof
  disagree.
- `crates/btungsten-wb002-core` (moved from `scripts/btungsten/wb002-rust`)
  is the proven core, now a workspace crate the model links.
- The battery (`tests/wb002/`, 24 tests) and the WASM corpus harness
  (`src/bin/wb002-wasm-equiv.rs`, boot readiness in `src/ready.rs`) drive
  the Rust model. `wb002-wasm.yml` builds and runs the Rust harness.

## A finding the Rust-first rule produced on its first run

The proven-step replay stopped the adapter 600-step history on asset
100000000000005, head 9 (detach): the tables said the detached child
belonged to `authorx`, the proven step said `ed`. Upstream SA.cpp:581 sets
`s.owner = owner` on detach; the retired JS port kept the child's
attach-time owner, so a child detached after its container changed hands
came back owned by the OLD holder. The JS battery and the 46-step corpus
never walked that path. Fixed in the Rust model (cited in place).

## Boundaries

- The SAW proofs cover the Rust model cores against the Cryptol specs.
  The 2021 wasm link is the executed corpus (sampled), never a proof.
- `Ed25519.cry` is checked on closed terms. It is not a proof about
  libcrux; libcrux's correctness proof is HACL*'s F* development. A SAW
  proof of libcrux against `Ed25519.cry` is not claimed.
- Dependency audit (law 3): `cargo tree -e normal -p btungsten-wb001`
  pulls libcrux-ed25519 0.0.9, libcrux-hacl-rs 0.0.5, libcrux-sha2 0.0.8,
  libcrux-traits 0.0.8, libcrux-secrets 0.0.6, hax-lib 0.3.7, rand 0.10.2,
  rand_core 0.10.1 (proc-macros at build time). RustSec advisories naming
  them, each cleared by version: RUSTSEC-2026-0026 and -0075
  (libcrux-ed25519 `generate_key_pair`, patched >= 0.0.6 / 0.0.7; 0.0.9
  pinned, and the function is never called), RUSTSEC-2026-0212
  (libcrux-secrets aarch64 select/swap, patched >= 0.0.6; 0.0.6 resolved),
  RUSTSEC-2026-0097 (rand `rng()` with a custom logger, patched >= 0.10.1;
  0.10.2 resolved). cargo-audit is not installed on this box; the
  advisories were read from rustsec/advisory-db directly.
