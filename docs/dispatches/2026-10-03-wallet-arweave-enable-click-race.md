# Wallet check: the Arweave enable-then-click race, repaired and guarded

2026-10-03. Seat 3 (Claude Code). PR #339, branched from main `fd423f3fa`.

The `wallet` check went red on unrelated commits (run 37108235973 attempt 1 on PR #320 head `a2f12898c`, while run 37108240704 on the same head passed). `e2e/wallet-arweave.mjs` enabled the intentionally unfunded publish control `#arw-go` in one Playwright step and clicked it in the next, at two sites. The page's own balance refresh re-disabled the button between the two, and Playwright waited 30 s for an enabled element.

Both sites now enable and click inside one `evaluate`. Production wallet code is unchanged. The other wallet batteries carry no enable-then-click shape.

The 2026-10-02 zblood dispatch said this repair had landed. It had not on main; that dispatch carries a forward correction.

A static check, `scripts/lint-e2e-enable-click.mjs`, now runs in the `static` job. It fails the run if any e2e file enables a control inside an `evaluate` call and clicks it after that call closes, on the same line or within the next three code lines. The boundary is the browser task, not the physical line (review of `7b84a52c7`, whose first cut keyed on line co-location; the change itself is in `7b6edcd83`). It tests itself first: the two-step shape must be caught on two lines and on one, and the one-task shape must pass on one line and across several. Control: the pre-repair `wallet-arweave.mjs` from `fd423f3fa` is flagged at lines 183 and 284; the tree as repaired reads clean.

Local receipt for the repair: `WALLET_REG=<reg> node e2e/wallet-arweave.mjs`, three runs in each of cypherpunk, bee and raver, 40 passed and 0 failed every time. Nine green runs do not prove an intermittent race is gone; the one-task shape leaves no gap for the refresh to land in, and the static check keeps the shape from returning.

Second review correction (review of `7b6edcd83`; the change itself is in `efb34ec92`): the check now blanks comments, strings and regular-expression literals before it reads, accepts whitespace before the call paren, walks nested e2e directories (285 files), and counts only a click on the control that was enabled. A click on something else inside the task no longer clears the enable; a later click on a differently named control is no longer flagged; anything it cannot tell apart is flagged. Twelve self-test shapes. It still reads source text and not a syntax tree: an enable inside a string passed to `evaluate`, or in a helper the callback calls, is not seen.

Third review correction (review of `efb34ec92`; the change itself is in `ac170a9e1`): a slash after the paren closing an `if`, `while`, `for` or `with` condition is now read as opening a regular expression, where after any other closing paren it divides. Fourteen self-test shapes. Telling a regex from a division stays a rule of thumb, not a grammar.

Fourth review correction (review of `ac170a9e1`; the change itself is in the commit that adds this paragraph): `evaluateAll` is read as a browser task, and an enable is now any write to `disabled` that is not a literal true, plus `removeAttribute('disabled')` and `toggleAttribute('disabled')` without a true force. Nineteen self-test shapes. The commit attributions in the three paragraphs above were corrected in the same commit: each had named the commit under review as if it held the change.

Fifth review round (review of `5ea54566c`; the change itself is in the commit that adds this paragraph), and a change of design. The review found three more ways past the reader: a disable exemption that only looked at the start of the right-hand side, a click deferred with `setTimeout` counted as atomic, and two locator spellings for one button treated as two controls. Five rounds each found a real hole, so the check no longer tries to judge whether an enable is safe. Everything in the four correction paragraphs above describes a reader that is now deleted.

What stands now. `e2e/lib/enable-click.mjs` exports `enableAndClick(locator)`, which enables and clicks in one synchronous browser task; both sites in `e2e/wallet-arweave.mjs` call it. `scripts/lint-e2e-enable-click.mjs` reads the raw text of every JavaScript file under `e2e/` (286) and fails on any write to `disabled` that is not a whole-statement literal true, unless the file is on a ledger in the script with its reason and its exact count. Seven files are on it: the helper, three Node mock elements, two tests that enable to read a computed colour and restore without clicking, and one that matches regex source against page HTML. A count that drifts either way fails. Sixteen self-test shapes. Control: the pre-repair `wallet-arweave.mjs` from `fd423f3fa`, placed under `e2e/lib/`, fails with two writes. Limit: an enable that never names `disabled` is not seen.

Receipt after the helper change: `WALLET_REG=<reg> node e2e/wallet-arweave.mjs`, three runs in each of cypherpunk, bee and raver, 40 passed and 0 failed every time.

Sixth review round (review of `c8f451f10`; the change itself is in the commit that adds this paragraph). Two findings, both taken. Compound assignments (`&&=`, `^=` and the rest) now count as writes, as do the bracket form `['disabled'] =` and an `Object.assign` that sets `disabled`. And the helper is pinned, not merely counted: comments aside, `e2e/lib/enable-click.mjs` must be exactly its one statement, so a rewrite that enables in `evaluate` and clicks in a `.then` fails. The ledger is eight files, with `first-work.test.mjs` added for a mock's `Object.assign` initialiser. Twenty-three self-test shapes. Controls: the pre-repair `wallet-arweave.mjs` fails with two writes, and the helper rewritten as a split enable-then-click fails the pin.

Seventh review round (review of `649b0839c`; the change itself is in the commit that adds this paragraph). Three findings, all taken. An `Object.assign` that sets `disabled` is now read across lines, to the call's closing paren. The ledger no longer exempts a file by count: each entry pins the exact snippets that hold its writes, and every write in the file must sit inside one, so a restore edited to an enable with the count unchanged fails. And the helper keeps what a real click would have checked: in the same task, before it enables, it refuses a control with no box, not visible, or covered at its centre. Twenty-eight self-test shapes. Controls: the pre-repair `wallet-arweave.mjs` fails with two writes; `blight-market-eternal.test.mjs` with its restore changed to `= false` fails its pin; the helper presses a plain disabled button and refuses a covered one, a `display:none` one and a `visibility:hidden` one. Receipt with the new helper: `WALLET_REG=<reg> node e2e/wallet-arweave.mjs`, three runs in each register, 40 passed and 0 failed every time.

Eighth review round (review of `ca546113b`; the change itself is in the commit that adds this paragraph). `b.disabled--` and the other increment and decrement forms now count as writes, and the scan that bounds an `Object.assign` call skips parens inside strings, templates and comments; a call whose end is never found is read to the end of the file. Thirty-three self-test shapes. Standing limit, restated: this check lists the ways to write `disabled` that it knows. It is a tripwire for the shape that went red, not a proof that no test can enable a control.

Ninth review round (review of `d3a2d7b7b`; the change itself is in the commit that adds this paragraph). Inside an `Object.assign` call, `disabled` as a shorthand key (`{ disabled }`) now counts as a write. Thirty-six self-test shapes.
