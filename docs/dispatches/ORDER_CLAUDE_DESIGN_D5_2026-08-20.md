## 1 · The ask — three artboards through the D4 procedure

**D5-a, D5-b, D5-c: bee · raver · cypherpunk** — one worked screen each (recommend the
university course view and the bFood hexagon as the two canvases), showing what each
register does to density, chrome, and colour temperature at the same information state.
The constraints that are already law, so the artboards bake them in rather than discover
them:

1. **One set of constants, three renderings** — a register changes how facts are dressed,
   never which facts are true. The artboard should show the same cell/sentence at all
   three registers, visibly identical in numbers.
2. **A register is a preference, not a tier** — nobody proves anything to get the bee
   version; the visual language must not make bee look like a downgrade (the current
   functional risk: "guided" reads as "less" when it is merely "gentler").
3. **Raver is vivid, not louder data** — decoration lives in the chrome layer
   (D-F5's lawful home), never in the data encodings.
4. **Cypherpunk is dense and receipts-forward** — file paths, commit hashes, raw numbers
   adjacent; think workbench-tier.
5. **The unification law rides every artboard:** wherever colour communicates, its
   mandatory label renders in the user's top-2 languages with machine drafts badged —
   include one label-as-corpus-record specimen per artboard.
6. **Gating is the founder's late-beta ruling (U-1 open)** — the artboards must work
   ungated; if you draw a gate, badge it CONCEPT — NOT BUILT.
