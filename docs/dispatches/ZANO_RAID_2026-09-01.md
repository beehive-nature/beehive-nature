## 1 · ZANO AT HEAD — the fork is not coming; it LANDED

**Hard Fork 6 activated at block 3,833,000, August 25–27, 2026 — five days ago.**
(Zano's own countdown post; CoinMarketCap confirms activation ~Aug 25–26.)
What HF6 actually ships:
- **Gateway Addresses** — exchange/bridge-ready account-style addresses (one
  directly tracked balance, instant sync) without degrading normal-user privacy.
- **Trustless native bridging (Bridgeless)** — native ZANO to Ethereum, TON,
  Solana — no custodian. Threshold-signature design.
- Hardening: stronger consensus, refined decoy selection, per-output payment
  IDs, resilient mining pools (dry-run), anti-DoS, SOCKS5/Tor, hardened RPC.

**Zano's true surface (Claude's claim — CONFIRMED):** confidential assets
(hidden amounts AND hidden participants, Zarcanum HF4), aliases, atomic swaps,
the first fully private PoS staking, a DEX for confidential assets, on-chain
anonymous voting (Q4 2025), offline signing, hardware wallets. **No general
VM on L1, and none on the roadmap.** Zano = private value rail, not a private
application layer. Exactly as read.

**The contract answer is ZEL, not "Hadron."** "Hadron" appears NOWHERE in
Zano's roadmap or announcements — Claude's term was wrong (or another
project's). The real initiative, from the July 17, 2026 roadmap update
(Monthly Project Update #22): the **Zano Execution Layer — an independent EVM
sidechain** connected by a threshold-signature bridge, bridged ZANO as gas,
standard Solidity unmodified. Public testnet Q3 2026 (NOW), mainnet target Q4
2026. Note the shape: contracts run on a PUBLIC sidechain; privacy stays on
L1. ZEL is Zano's performance layer, not a private VM.

Coming next: Zenith (pure PoS, design published), FCMP++ research (full-chain
membership proofs), alias marketplace/auction, multisig, dynamic fees.

## 2 · THE VAULTA SIDE — three verifications

**a. The sunset is real.** Vaulta's own page: EVM infrastructure support
**ended October 8, 2025**, migration directed to exSat EVM, gas token flipped
to $A on October 1. Claude's portability warning = CONFIRMED. Consequence for
the estate: the VM-as-contract PATTERN is proven (VaultaFoundation/evm-contract,
silkworm inside the contract), but the foundation's instance is dead —
anything we build on Vaulta, WE own. Consistent with the first-party-only law.

**b. The deciding question is ANSWERED — Claude missed it.** The claim that
stood between "sovereign privacy layer" and "impractical": can an Antelope
contract verify ZK proofs natively? **Yes — the host functions ship in the
CDT.** CDT v4.1.0+ (requires Spring v1.0.0+ nodes) added native intrinsics
originating from the pEOS proposal: `eos.evm.keccak256`, `eos.evm.blake2f`,
`eos.evm.modexp`, and **`eos.evm.alt_bn128_add` / `_mul` / `_pair`** — the
pairing operation, native, shipped to power EOS EVM's precompiles. A
Groth16-over-BN254 proof (the Ethereum-standard SNARK verification path)
verifies through exactly those calls — **native cost, not WASM-emulated.**
Scope limit, honestly: **alt_bn128/BN254 only.** BLS12-381 and the Pasta
curves (Halo 2, most modern recursion) have NO host function — those verify
in pure WASM at likely-impractical CPU cost. The sovereign layer, if built,
speaks BN254 SNARK.
- REMAINING MEASUREMENT (small, one, half a day): confirm `alt_bn128_pair` is
  callable from a FRESH contract on Vaulta mainnet today (the intrinsics
  shipped FOR the EVM contract; post-sunset general availability must be
  proven, not assumed) and measure µs + billed CPU per pairing and per full
  Groth16 verification against the per-block CPU budget. Bench on a local
  Spring node or jungle4.

**c. exSat verified.** Antelope-framework Bitcoin docking layer, mainnet Oct
2024, hybrid PoW+PoS, EVM via the same contract lineage. The reusable move is
exactly as Claude framed it: **you don't need a new chain to get a new VM.**
