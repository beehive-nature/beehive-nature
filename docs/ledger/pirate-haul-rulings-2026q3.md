## License gate — new entry

- [stated] 2026-07-25 **AUTONOMI IS GPL-3.0** — the finding that changes the board. Verified from repo LICENSE in the credible-exit audit: both `maidsafe/autonomi` and `self_encryption` are GPL-3.0 (as are ant CLI, ant-node, ant-node-manager, ant-bootstrap). This is BNR's OWN durable-storage layer, so it is a structural constraint on internal architecture, not just an external raid target. TWO PATHS, TWO OUTCOMES: (a) **network-API path** — talk to an authenticated gateway / antd over REST/gRPC: no linking, no copyleft, CLEAN; (b) **WASM client path** — compiling the autonomi crate to WASM for the browser LINKS the GPL crate, and shipping that bundle to users is distribution, so copyleft applies to the bundle. PRECISION NOTE (Seat-1, refining the founder's framing): GPL-3.0 differs from Firecrawl's AGPL-3.0 in the trigger — AGPL adds the §13 network-use clause, GPL does not. GPL fires on DISTRIBUTION of a linked work, not on running it as a service. So a server-side BNR component that links autonomi and is never distributed does not trigger copyleft; a browser bundle shipped to users does. The adapter-isolation strategy works cleanly across a PROCESS boundary (separate binary, IPC/network) and is murkier for in-process dynamic linking — prefer the process boundary. FORMAL RULING STILL NEEDED before the adapter spec, but the CORRECTION IS ACCEPTED (founder, same session): "I overstated the parallel… Autonomi constrains BNR less than Firecrawl does." Settled position: the only real constraint is the WASM-to-browser path, and the process-boundary adapter pattern sidesteps even that. Sits on the license gate alongside crawl4ai (pending raw LICENSE read) and Firecrawl (AGPL core / MIT SDKs)
