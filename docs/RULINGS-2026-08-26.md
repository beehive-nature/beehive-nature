# RULINGS — 2026-08-26
### Founder decisions, with the conditions attached. Citable by all seats.

---

## R1 — The orbit freeze: DO NOT LIFT

Founder, 2026-08-26, after a seat's estate-wide cache-key sweep edited the
frozen file and turned CI red for fifteen pushes:

> "FREEZE RULED: DO NOT LIFT. orbit.html stays byte-pinned at 6e54b80d…, keeps
> tour.js?v=22, and the version skew is accepted. Reason beyond the cache: the
> Rail 2 Arweave anchor payload pins those exact bytes — lifting the freeze
> would invalidate a pin destined for permanent storage."

**The ruling, in force:**

1. **`surfaces/forge/orbit.html` is byte-pinned at**
   `6e54b80deff87861e4ad0134799cbd8a28492ed9e851b26bdfd597f4258a6b29` <!-- PUBLIC-CONSTANT: frozen orbit.html committed-blob sha256 -->
   (8,644 B, committed blob). `e2e/forge-freeze.mjs` enforces it on every push.
2. **The pin is NOT to be updated to make a build pass.** If a sweep, a
   refactor or a cache bump moves those bytes, the fix is to restore the file —
   never to re-pin. A seat that edits the pin to clear a red CI has broken the
   thing the pin exists to protect.
3. **The version skew is ACCEPTED and is not a defect to report.** orbit.html
   keeps `tour.js?v=22` while the rest of the estate moves on. A `?v=` is only
   a cache key on the same file, so the frozen page still loads the current
   rider; a returning visitor may be served a previously cached copy there.
   That is the price of the freeze and it is paid knowingly.
4. **The reason that outranks the cache law:**
   `surfaces/forge/orbit-arweave-anchor.md` — the Rail 2 ceremony's ready state
   — carries `6e54b80d…` in its payload table as the renderer hash the
   orbit-manifest pins. Those bytes are destined for permanent storage.
   Changing them invalidates an anchor that cannot be recalled.
5. **Tinkering forks** to `surfaces/forge/orbit-v2.html`, which is not frozen
   and is deliberately not presented on any door
   (`e2e/university-smoke.mjs` REACHABILITY_EXEMPT carries the reason).
6. **Sweeps use `scripts/bump-rider.sh`**, which reads the frozen path from the
   gate itself, names any frozen file it skips rather than skipping silently,
   and runs the freeze before a bad sweep can reach a commit.

## R2 — The receipt is CI's verdict, not a seat's suite list

Founder, 2026-08-26:

> "REPORT CI'S VERDICT, NOT YOUR SUITE LIST. From now on every report ends with
> the repo's own CI result for the pushed commit — the run, and green or red.
> Your chosen suites can still be listed, but they are not the receipt. This is
> the founder's existing law extended by one verb: shipped = the live URL,
> green = the CI run."

**The ruling, in force:**

1. **Every report of shipped work ends with the repo's CI conclusion for the
   pushed commit** — the run id and green or red. `gh run list` /
   `gh run view` already provide it; no new tooling and no new gate.
2. **A seat's own suites are evidence, never the receipt.** They may still be
   listed, and should be, but "the gates I ran are green" is not a claim that
   the build is green.
3. **Why this became law:** on 2026-08-26 a seat reported green on
   university-smoke, doors, estate-review and estate-source across fifteen
   consecutive pushes while `tests` failed on every one of them. Every
   individual report was true. The pattern was still false, and it was
   invisible from inside the reports — the founder found it by looking at the
   repo. Running the gates you chose is not the same as running the gates the
   repo runs.
4. **Red CI is reported as red**, in the same message, with what broke and
   whose it is — not deferred to the next turn.

*Both rulings recorded the day they were made. R1 supersedes any prior reading
that treated the orbit pin as adjustable; R2 extends the receipt law
(ORDERS-1 §2.1, "no ✅ without a receipt") to the build itself.*
