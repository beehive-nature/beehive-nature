# x402 RAID — RULE-vs-SERVER SORT — 2026-09-01

Reading half of the x402 raid (Cowork seat). Four repos read at source, at the HEAD
commits recorded in VERIFIED-FACTS A56–A59 (licence register). Code was judged, never
the coder — no author research was done.

**Sort rule.** RULE = runs with no seller-operated box (pure library, on-chain contract or
ledger record, client-side logic, static data/schema, protocol text, CLI that only talks
to a public chain). SERVER = needs an operator-run process/host (API server, facilitator,
DB, cron, hosted web, relayer). "Client-side, user-run" processes (an MCP tool on the
buyer's machine) count as RULE — the seller's disappearance does not take them down.

**Shared facts across all four.** All four are Hedera builds (testnet), x402 v2 via
`@x402/core` + `@x402/hedera`. None uses the Coinbase/CDP facilitator. Two (Tally, qisma)
run their own facilitator; xorv runs one in-process with `hosted` = x402.org as fallback;
pinout points at `https://x402.org/facilitator`. Receipts in all four are anchored to
Hedera Consensus Service (HCS) topics, which stay readable from any public mirror node
after every server dies — that is the common RULE spine.

Facilitator: **self-hosted**, default `http://localhost:4020`; `/supported` advertises `signers: {"hedera:*": [FACILITATOR_ACCOUNT_ID]}`. Chain: Hedera testnet only (schema is `z.literal(NETWORK_TESTNET)`), native HBAR, token/NFT transfers rejected (`validate.ts` rule 5.2), no smart contracts.

**How the split is enforced with no server:** the buyer's Hedera signature covers the whole transaction body, and `CryptoTransfer` is atomic — all credits land or none do. The facilitator adds only fee sponsorship + submission + nonce memory. A buyer can set itself as fee payer and submit directly; the seller then verifies with `inclusion.ts:verifyInclusion` alone (memo/nonce/credit, no keys). The one stateful piece left is single-use nonces.

## RULES → estate seats

Seat key: **z3.3** = VENDING / meter · **z3.1** = bSigner / `crates/` · **z3.2** = surfaces · **z2.1** = privacy contract. Each seat reads its lines here instead of the repos. Mechanisms, not files, travel — the estate is Vaulta/Arweave/Autonomi, not Hedera, so every Hedera SDK call is replaced by the estate's own rail; what is lifted is the RULE shape.

## What is NOT lifted (SERVER class — the dependency the estate replaces)

Recorded as boarding fact, not as option: pinout's Azure VM + Daytona/Modal + OpenAI/OpenRouter + custodial `club/` wallets; Tally's Express facilitator, Gemini-metered seller, Vercel `/api/buy` with a server-held buyer key; xorv's single broker (registry, matcher, facilitator, fee payer, DB in one process) and the server-side demo signer; qisma's facilitator nonce set held in RAM (replay protection dies on restart). Every one of these is the class the bMesh + local models + b-meter replace. The one honest structural residue in all four: **single-use nonces need SOME stateful party** — in the estate that party is the meter contract on Vaulta, not a box.
