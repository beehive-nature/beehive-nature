# bMaiL — THE PICTURE (one screen)

Six outside things were read cover to cover — one hosted chat tied to wallet addresses,
one messaging network, one wallet-mail company that shut down this May, one chat protocol
whose company moved on, the open message rail the estate already runs, and one Bitcoin
naming standard. The question was simple: **one inbox, one name, where people and agents
send mail, messages and money — and what happens the day the hosting stops.**

## Before → After

| today | after the slices land |
|---|---|
| A seat has a mailbox on the estate's own box, and nothing reads it. Mail arrives and waits in a folder. | Mail arrives, a **doorbell** rings in Buzz (never the contents), and the owner opens it on their own device. |
| A name on the registry tells you who owns it and when it expires. It does not tell you how to reach them. | A `.a` name **resolves to an inbox** — keyless, from the chain, like looking up a phone number you were given. Human `.b` names never get a public mapping; that is the law, not a gap. |
| To pay someone you type an account and a memo. To message them you find another app. | You type a **name**. One signature pays them, and the memo is the message. The payment is the receipt. |
| A seat's mail address, its Buzz key and its `.a` name sit on one card, and the card says they are not bound to each other. | Each seat **signs one receipt** joining the three. The card shows a verified binding, not a disclaimer. |
| Private messages between seats leave from one shared key on the box. | A member's own wallet **wraps a private message** to the reader's inbox relays, signed in the page, no key ever crossing. |
| A message can be read by whoever runs the relay, forever. | A message on the relay is a **pointer with a fuse**; the content lives with its owner. Nothing addressed to a human is ever mirrored to a permanent store. |
| The estate says, four times, "no inbox". | One page, three registers, lists what a name received: doorbells, pointers, payments. |

## Comes home / stays hosted

| **COMES HOME** (runs on the hive with no outside box) | **STAYS HOSTED** (the class we replace) |
|---|---|
| Sign in with the key you already hold — no email, no password | Blockscan's closed web app, its 5-day message store, and its "no guarantee of availability" |
| An agent reads its inbox with its own key, never an operator API key | Blockscan's rule that API-key holders and bots lose end-to-end encryption |
| One name, many devices; each device key revocable | XMTP's seven permissioned nodes, chosen by one company through a form |
| Relay storage priced per byte-day by our own meter, charged to the sender's side | XMTP's USDC payer registry on a rented L3, and its 30-to-60-day fuse |
| Inbox bytes live where the owner holds them; the relay is a cache | Mailchain — shut down 5 May 2026, "all user data permanently deleted", encryption and all |
| Keys re-derived from the soul on every device; nothing to escrow | Push's private keys held encrypted on the company's nodes, under a company that has moved to a different product |
| NIP-17 wrapped messages to the reader's chosen relays; NIP-05 name→key as a static file we serve | A Lightning zap's recipient-side server; a Cashu mint's custody |
| A Vaulta transfer with a memo — already in the wallet — as the pay-to-name message | DNS-based payment records; the registry row already does this |
| "A message is a pointer, never content" — already the estate's law | — |

Everything on the left works the day any of their hosting stops. Everything on the right
is what stopped, or will.
