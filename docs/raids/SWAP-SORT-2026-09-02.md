**Sort rule.** RULE = runs with no operator-run box: software the member runs on their own machine,
on-chain script, pure library, protocol text. SERVER = needs some third party's hosted service.

**One-line verdict.** BasicSwap and the Particl marketplace are RULE almost end to end — the
"server" is every member's own node gossiping encrypted messages — and the two exceptions are
price hints and download mirrors. The Zano half of the order is a **denial**: no BasicSwap
integration exists at any primary source (A63), and Zano's own HTLC is **removed at HEAD** (A64).

**What it was (last snapshot `1b1cc032`, so the audit is grounded, not guessed):**
`struct txout_htlc { hash htlc_hash; uint8_t flags; uint64_t expiration; public_key pkey_redeem; public_key pkey_refund; }`
inside `tx_out_bare` (`currency_basic.h@1b1cc032:290-307`) — a **bare, explicit-amount** output,
no commitment, no concealing point. `struct txin_htlc : txin_to_key { std::string hltc_origin; }`
(`:252`) — preimage in the input. Creation in `construct_tx` (`currency_format_utils.cpp@1b1cc032:1342-1384`);
deterministic origin `generate_origin_for_htlc` (`:1175-1185`) = `cn_fast_hash(pkey_redeem ‖ pkey_refund ‖ spend_secret_key)` —
**the spend secret was a hash input on the host wallet**. Spend: ring size exactly 1 (`:2473-2477`),
signed by `crypto::generate_ring_signature` — CryptoNote NLSAG (`:2148-2160`); `generate_CLSAG_GGX`
(`:2125-2132`) reached only for `txin_zc_input`. Consensus: `check_tx_input(const txin_htlc&)`
(`blockchain_storage.cpp@1b1cc032:5873-5920`) — `sha256(hltc_origin) == htlc_hash` (or RIPEMD160 by flag),
then `check_input_signature`; redeem-vs-refund key chosen by expiry (`:8077-8079`).

| HTLC element | frozen proto | signing path |
|---|---|---|
| `txout_htlc` | **DOES NOT TOUCH** — `ZanoSignSetOutput` has no hash/expiry/refund-key fields; `ZanoSignSetOutputAck` returns Zarcanum-only artefacts (amount_commitment, Q, ecdh_info) a bare output has no slot for | **DOES NOT TOUCH** bppe (no range proof on bare outs), balance double-Schnorr, 1/8 scaling |
| `txin_htlc` | **DOES NOT TOUCH** — `ZanoSignSetInput` ring members require `amount_commitment`/`blinded_asset_id` (none on bare outs) and have no `hltc_origin`; `ZanoSignInputAck` returns a CLSAG_GGX signature where an NLSAG was needed | **DOES NOT TOUCH** `generate_CLSAG_GGX`. Key image `I = s·Hp(P)` is the same derivation (`generate_key_image_helper`) — moot, since consensus no longer accepts the input |
| `tx_prefix_hash` | TOUCHES only as opaque `m` (host serialization would carry `hltc_origin`) | — |

**Answer:** v0.3 firmware could neither create an HTLC output nor spend an HTLC input — correctly,
because (a) the frozen fields cannot express either object, (b) HEAD consensus cannot deserialize or
validate them, (c) on the last release that had them, creation was already dead post-HF4. **Nothing is
missing from the proto for the current chain.** One standing note, not a change: the removed origin
scheme hashed the raw spend secret on the host; any future revival of that pattern collides with the
frozen invariant that `s` never leaves the device — a reason to keep HTLC out of scope, not a gap.
"Atomic swaps" in Zano's own tree was this HTLC (`atomics_*` RPC at `wallet_rpc_server.h@e5afb6b0:130-133`,
`tests/core_tests/atomic_tests.cpp` at `035f233b^`); docs.zano.org wording: UNVERIFIED (not in repo).

**Consequence for the Zano-swap lane:** with HTLC gone, a Zano leg on any atomic-swap DEX would have
to be the **adaptor-signature / no-script side** (the way BasicSwap treats XMR), which is exactly
the surface the frozen CLSAG proto already signs — no proto change follows from this raid.
