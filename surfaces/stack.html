Identity

bPQ keys + sealed objects

code present

Get post-quantum keys from your recovery words, and seal files only you, or people you pick, can open.

Evidence and limits

bpq.js derives ML-DSA-65, X-Wing (ML-KEM-768 + X25519) and a vault key from the root the recovery words carry, plus an SLH-DSA-SHAKE-256f succession key of which only a hash is published; the bzpq1 id commits to both. Sealed objects (SPEC-BPQ-1) are AES-256-GCM segments with per-reader key slots that name no reader. crates/bsigner/src/bpq.rs derives the same keys and opens the same objects natively; both implementations must pass surfaces/bpq-vectors.json in CI. @noble/post-quantum is self-audited and the RustCrypto crates are unaudited, so their agreement is a cross-check, not an audit. Keys live in browser memory while the keychain is connected; no hardware custody.

      ENGINEER FAQ — what breaks when X goes down, answered from the architecture

      Every answer below is a property of the design, checkable in the source — not a promise. Where the honest answer is "that hurts today," it says so, with the mitigation's state.
      failurewhat actually happens
      GitHub Pages goes downThe checked-in public files can be hosted elsewhere. A clone does not contain private service state, browser storage or every external dependency. Already-loaded functions may continue; new page loads and network-dependent actions can fail until another host is available.
      the GitHub org is deleted Git is the medium: every clone carries full history, and the mirror manifest publishes sha256es of the evidence corpus, so any copy can prove it is the real one. The corpus, specs and receipts are AGPL — legally re-hostable by anyone the moment we cannot.
      a VPS / relay disappearsFunctions using that service may stop. Recovery depends on its actual replicated state, backups and tested runbook. Planned chain or ANT/AR anchoring is not evidence that every relay is already recoverable.
      an RPC endpoint dies (Base/ETH/Arbitrum/Vaulta)Some adapters implement endpoint fallback; verify the specific adapter and its error behavior. A failed read must remain distinguishable from a zero balance. No fresh end-to-end failover sweep is claimed here.
      Autonomi has an outage — or dies entirelyRetrieval depends on reachable storage and the required recovery material or DataMap. An alternative adapter does not automatically recreate unavailable data. A second copy only helps when it was actually stored and its retrieval verified.
      Arweave stops accepting writesNew writes through that route fail or wait. Other routes require their own quote and authorization; an unuploaded artifact has no redundant permanent copy merely because two adapters exist.
      your nodes go down (the farm) Nodes are yours, on your machine — the network re-replicates chunks around absence, and your DataMaps keep working from any client: retrieval needs the network, not your nodes. Earnings pause; nothing is lost but uptime.
      the language corpus fails to fetch Every page falls back to English and says so — the picker's counter reads the truth (⚙ 0/N) instead of silently anglicizing. A withdrawn tongue stops rendering estate-wide while its history stays in the file.
      localStorage is cleared / you switch devicesPreferences and any locally stored application state can be lost. Recovery depends on the particular feature and retained recovery material or backups; do not assume browser storage contains only preferences.
      this page lies to you The standing answer: don't trust these pages either. Every claim links its source; the git history is the audit log; the university teaches the checking. The design goal is not "trust us" — it is maximum verifiability at zero credential cost.
