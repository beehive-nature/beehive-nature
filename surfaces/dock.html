What this is, in three sentences

Beehive Nature is a coordination kernel written in Rust — a small core that knows almost nothing on purpose: identity, settlement, escrow, disputes, reputation, and one canonical event log. Everything specific plugs in around it, so chains enter as adapters and applications as dApps, and swapping the settlement chain underneath does not change the heart. Its first target is private commerce between two strangers who trust neither each other nor a middleman: the payment waits in a Zano escrow that only a Trezor can co-sign to release, disputes are settled on evidence, and standing is earned by acting well rather than bought.

Status, without rounding up. This is a kernel under construction, not a running marketplace. The cryptographic design is source-confirmed, the wire contract is frozen at proto v0.3, and host-side Zano derivation is proven against stock Zano — you can reproduce that yourself in one command, below. Firmware and legal review are the unstarted work between here and anything an end user touches.

The ledger that never rounds up is STATUS.md. Read it before you believe anything else, including this page.

Run something in under five minutes

With a Rust toolchain — reproduce the Zano derivation proof

git clone https://github.com/beehive-nature/beehive-nature.git
cd beehive-nature
cargo test -p chain-zano
Measured on a cold clone with an empty cargo cache: clone 2 seconds, then 14 seconds to download, compile and run — 9 passed, 0 failed, 1 ignored. The ignored test names its own blocker: it needs a (spend_secret → public_key) vector, and a real spend secret is deliberately never committed to this repo.

Before you commit anything

git config core.hooksPath .githooks
Enables the pre-commit secret scan. It is mandatory, it is one command per clone, and CI re-runs the same scan on every push — so a miss here becomes a red build rather than a leak.

With no toolchain at all

The surfaces are static HTML and are live now: beehive-nature.github.io/beehive-nature/surfaces/. Nothing to install, nothing to sign into.

If you want the sharpest single example, open recover.html and watch your browser's network tab: it rebuilds keys from a recovery phrase and makes zero network requests doing it. That is the house style — a page you can save to disk and still trust in ten years.

Where to ask a question

  • GitHub Discussions — open questions, "why is it built this way", "is this real yet". No wrong questions here.
  • GitHub Issues — something is broken, wrong, or missing. A reproduction beats a description.

Both are open on the kernel repo today. There is no mailing list, no forum, and no support address — if this page told you otherwise it would be inventing one.

How your work is licensed and credited

Licensed: the kernel and LOVErnment-DAO are AGPL-3.0-only. Contributions enter under that license.

Signed off, not signed away. Contributions require a DCO sign-off — git commit -s — certifying the Developer Certificate of Origin: that you have the right to submit the work under this repository's license.

There is no CLA, and that is deliberate. Contributors retain their own copyright; nothing is assigned to any steward. The practical consequence is the point: the license can never be changed without the consent of every copyright holder — including yours. The reasoning is written down in docs/LICENSING.md.

Credited: co-authors are recorded in the commit itself with Co-authored-by: trailers, so credit travels with the history rather than with a page someone can edit later. Every machine seat working in this tree is credited the same way, by name.

The full house rules — how findings enter the repo, and the verification principle that no external claim becomes an assumption until it is checked against source or a live system — are in CONTRIBUTING.md.

What is not built yet

A front door that overstates is worse than no front door, so:

The self-service roster wizard — specified, not built

A form that builds your contributor entry and opens the pull request for you was designed and never written. Until it exists, you contribute the ordinary way: open an issue, or open a PR. There is no wizard behind this page and no queue you are waiting in.

Firmware and legal review — unstarted

Repeated from the status note above because it is the single most load-bearing caveat on this page. Nothing here is ready for an end user's money.

This page runs no JavaScript — view source and check. No accounts, no cookies, no telemetry, no build step. It is one HTML file and one stylesheet.
