⚙ UNDER THIS DECK — the stack, said plainly (for builders)

How a deck like this is operated by our stack — and what is honest today: this page itself is the estate's static-fleet pattern (HTML + vanilla JS, zero server state, zero credentials, free to serve and free to read). The interactive production rails follow the same discipline, layer by layer:
FRONT · htmx + AlpineJS
Progressive HTML, never a framework maze. htmx swaps fragments over the wire; AlpineJS carries the small state (toggles, tabs, this very register switch's sibling patterns). The learning curve stays Apple-flat: the page IS the app, the browser stays the browser.
DATA · sqlite by default, postgres by function
Right-sized persistence. sqlite for every surface's own ledger and caches (zero-ops, embeddable, git-friendly exports); postgres where many writers or function demands arrive (metering at scale, the bounty board's queue). Never a database for a static page's ego.
KERNEL · the Rust crates
The instrument layer, tested and receipted: wallet-relay (the relay + heartbeat) · bindexer (Base measurement) · escrow-engine · reputation-engine · bmesh-meter (17 tests, mutation-proven). Keys are founder-held; every crate is keyless in operation.
LAW · what this deck may never do
Read and verify; never hold, never spend. No key input, no seed phrase, no write path anywhere on this surface. Wallet-gate law: any spending function sits behind a wallet session elsewhere in the eco; viewing — here and everywhere — stays open.
