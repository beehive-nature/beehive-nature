why invites break — two failure classes, both proven
1 · scheme-truncated pairing codes — the invite carries a code but the scheme prefix gets truncated during copy/paste, producing s://… instead of ws://… or wss://…. The Buzz app can't parse the scheme and silently refuses the relay — the stranger sees nothing, no error, no redirect. Always check the relay host before you join.

2 · TTL-expired static invites — join codes carry an expiry timestamp in the payload (visible when you decode the base64: the e field). When the epoch passes, the relay rejects the code — and the invite link on the directory still works as a link but produces an auth rejection at connection. The code looks fine. The relay says no.
