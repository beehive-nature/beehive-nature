Where the hosted room connects

  1. 1 / Your browserReads page assets and public room status. Video and chat wait for your action.
  2. 2 / Room hostReceives the playlist request and room pass. Serves video and reads the session receipt.
  3. 3 / Separate servicesChat connects through Buzz. Independent apps open only when you follow their links.

On arrival

Hosted pages request /live/health and /live/ticker/general.json every 5 seconds, plus the example manifest once. The host can observe IP address, request paths, timing and ordinary browser headers. Actual logs, retention and proxy configuration have not been checked here.

When you press Watch

attach() requests /live/general/master.m3u8?session=…; child playlists and segments carry that session number too. readSession() polls /live/session/…json every 4 seconds, with an additional 2-second poll while paused. The operator can associate requests with that receipt. The number is not a private identity credential.

When you open chat

The iframe loads /join/ only after Open chat. It shares this page’s origin: this is not isolation from first-party scripts or storage. Buzz handles its own authentication and messages. Chat encryption, membership enforcement and its downstream requests are not verified by this page.

What stays in this browser

The page remembers watch.session; the shared controls remember view and language choices. These are readable by scripts on the same origin. The shared rails badge can also read the saved public identity label and store an origin fingerprint. Those labels and fingerprints are not proof of authentication.

Encryption and metadata

HTTPS protects the connection to its TLS endpoint; it does not hide playback from that endpoint’s operator. The current HLS path does not establish end-to-end encryption or anonymous viewing. Networks can still observe traffic timing and volume. The example checkpoint is a shape-checked fixture, not proof that video was encrypted or retrieved from Autonomi.

Independent apps and chain checks

W@tch, JAMS.community and 3Speak receive a visit only when you follow their links; they then apply their own access and privacy rules. This page sends no Referer header on those links. The shared navigation’s ↻ rails check explicitly contacts eos.api.eosnation.io, with eos.greymass.com as fallback. Its initial badge is a dated snapshot, not a current security verdict.

Private viewing is not established

The checked-in live-door.mjs gates playlists on active receipt credit, but its segment handler does not recheck the receipt and its receipt endpoint has no caller identity check. This demonstrator must not be treated as private media access. Backend access enforcement, key custody, retention, and any claim of transaction unlinkability still need evidence.

No wallet signing, payment, raw x0x socket or real Autonomi write is started by this watch page. The encryption and payment boundaries of future adapters must be verified separately before use.

Stream setup · OBS / ffmpeg

The hosted player reads the existing playlist and session endpoints. The b balance and local-currency price are not supplied here; session credit is denominated in A. No wallet or payment is opened here.

stream URL  rtmp://127.0.0.1:19350/live
stream key  general?s=<the standing stream key>

ticker      curl -X POST http://127.0.0.1:18094/live/ticker/general \
              -H "authorization: Bearer <stream key>" \
              -H "content-type: application/json" \
              -d '{"now":"…","set":"21:00","next":"…"}'

Same-origin HTTP/HLS and Buzz room. Autonomi checkpoint shown above is a fixture, not a live subscription. Operator visibility includes IP, timing and requests on these hosted paths.
